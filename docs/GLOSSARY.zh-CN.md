# 术语表（新手版）

本文解释 crypto-portfolio-manager 当前文档、报告和代码中最常见的专业术语与缩写。
每一条都包含四部分：原词、通俗解释、在本项目中的具体含义，以及它可能怎样影响
组合决策。

本文解释当前内部契约；破坏性变更后的旧生成状态不受支持，需手动重新生成。
代码标识保留原样，方便在报告、JSON、配置和源码中搜索。--、缺失数据和失败状态
表示“未知或不可用”，不是可以随便填成零或安全的意思。

## 1. 复盘类型、结论与动作

| 术语 | 中文释义 | 本项目中的具体含义 | 对决策的影响 |
|---|---|---|---|
| **SNAPSHOT_REVIEW** | 快照复盘 | 读取当前持仓、历史和最新证据，做一次当前状态检查。 | 用于日常更新；仍会检查风险门和调仓阈值。 |
| **FULL_REVIEW** | 完整复盘 | 额外比较 NAV、回撤、BTC 基准、评分、目标配置和上一轮结果。 | 通常至少每 14 天一次，适合判断组合变化。 |
| **EVENT_REVIEW** | 事件复盘 | 针对安全、协议、治理、监管或其他可能改变投资 thesis 的事件。 | 事件来源覆盖不足或事件未解决时，可阻止新增风险。 |
| **Action** | 操作结论 | Python 根据证据、组合约束、风险门和调仓阈值生成的动作。 | 不能由一个分数直接替代。 |
| **INCREASE** | 增加 | 增加某资产的组合敞口。 | 必须通过风险、证据、稳定资金和集中度约束，并且金额大于零。 |
| **REDUCE** | 减少 | 降低某资产但仍可能保留仓位。 | 可能来自目标偏离、风险恶化或 thesis 变弱。 |
| **EXIT** | 退出 | 将某资产的目标权重降为零。 | 通常需要 thesis 破坏或明确的风险/资格问题；不是为了凑精确权重。 |
| **HOLD** | 持有 | 暂时维持当前仓位，不产生交易金额。 | 表示当前没有足够理由改变仓位。 |
| **WAIT** | 等待 | 暂不执行，等待更好的数据、价格结构或风险条件。 | 不是失败；技术数据不足、突破追涨或结构不清时都可能出现。 |
| **NO_TRADE** | 不交易 | 本轮没有合格的交易动作。 | 是合法且经常合理的结果，不是系统错误。 |
| **HOLD_ONLY** | 仅保留 | 可以在适当情况下保留已有敞口，但不新增风险。 | 常用于关键证据缺失或山寨币相对 BTC 的证据不足。 |
| **WATCH** | 观察 | 调整优先级，不是独立的交易动作。 | 通常表示偏离值得关注，但还没有达到执行条件。 |
| **thesis_broken** | 投资论点破坏 | 原先支持持有该资产的前提已经不再成立。 | 不应仅因暂时缺数而退出；确认后可触发减少或退出。 |
| **dry run** | 试运行 | 运行校验、分析和报告，但不追加 snapshot、decision 或其他历史记录。 | 适合先检查流程，不会改变运行时状态。 |

## 2. 组合与风险

| 术语 | 中文释义 | 本项目中的具体含义 | 对决策的影响 |
|---|---|---|---|
| **portfolio** | 投资组合 | 一组资产、稳定币和现金及其数量/价值。 | 风险和配置在组合层面计算，不是逐币独立优化。 |
| **position** | 仓位 | 组合中某一个资产的持有数量、价值和相关信息。 | Position P&L 只描述该剩余仓位，不代表整个组合收益。 |
| **asset** | 资产 | BTC、ETH、SOL 等可识别的符号及其统一分类。 | 分类来自 canonical policy；冲突的资产提示会被拒绝。 |
| **spot-only** | 仅现货 | 只研究直接持有的现货资产。 | 不使用杠杆、保证金、期货、永续或清算逻辑。 |
| **core** | 核心资产 | 默认的长期核心袖套，当前为 BTC 和 ETH。 | 核心分类不是无条件买入或目标配置保证。 |
| **satellite** | 卫星资产 | 核心之外、规模受限的精选大市值资产，当前包括 SOL、BNB、LINK、AAVE。 | 需要更高的证据门槛，并受卫星上限、信心和风险等级限制。 |
| **stablecoin / cash sleeve** | 稳定币/现金袖套 | 稳定币和现金视为同一个低风险资金篮子。 | 必须保持全局最低比例和当前 regime 要求的更高比例。 |
| **allocation** | 资产配置 | 决定每个资产应该占组合多少比例。 | 是组合级的确定性结果，不由单个分数直接决定。 |
| **weight** | 权重 | 某资产价值除以组合总价值的比例。 | current weight 与 target weight 的差异决定是否值得调仓。 |
| **target weight** | 目标权重 | 风险、评分、信心、regime 和上限共同得到的期望比例。 | 目标必须总和正确、满足稳定资金底线和集中度上限。 |
| **rebalance** | 再平衡 / 调仓 | 将当前配置向目标配置调整。 | 偏离低于 2 个百分点通常 HOLD，2–4 个百分点 WATCH，超过阈值才考虑交易。 |
| **benchmark** | 基准 | 用来比较组合表现的参照物。 | 主基准是 100% BTC；次基准是按现金流配置的 70/30 BTC/ETH 买入并持有。 |
| **risk budget** | 风险预算 | 组合允许承受的最大回撤额度，默认约为 15%。 | 它约束整体风险，不是每个资产都能单独使用一份预算。 |
| **drawdown** | 回撤 | 从历史高点到当前价值的下降幅度。 | 回撤恶化会把 regime 推向更防御的方向，不能产生更激进结果。 |
| **volatility** | 波动率 | 价格变化幅度的统计度量。 | 波动越高通常意味着仓位、目标或即时部署需要更保守。 |
| **concentration** | 集中度 | 组合过度依赖某一个资产或资产组的程度。 | 单资产上限和卫星上限会阻止高分资产无限扩大。 |
| **risk tier** | 风险等级 | 对资产风险和组合适配度的分层。 | 风险等级越高，目标和新增仓位通常越受限制。 |
| **risk regime** | 风险状态 | 组合和市场当前所处的风险环境。 | NORMAL、DEFENSIVE、CAPITAL_PRESERVATION 分别对应正常、防御和资本保全。 |
| **NORMAL** | 正常状态 | 没有触发更高风险防护的 regime。 | 可以按正常上限配置，但仍须通过所有风险门。 |
| **DEFENSIVE** | 防御状态 | 趋势、波动、回撤、流动性或事件使风险升高。 | 提高稳定币目标并收紧卫星上限。 |
| **CAPITAL_PRESERVATION** | 资本保全状态 | 出现严重回撤、重大事件或系统性风险。 | 重点保护资本，提高稳定资金目标，阻止不必要的新风险。 |
| **stable floor** | 稳定资金底线 | 稳定币/现金最低权重，取全局底线与当前 regime 目标中的较高值。 | 任何目标配置都不能突破它。 |
| **opportunity cost** | 机会成本 | 选择某资产时放弃的替代选择，尤其是 BTC 的风险/收益机会。 | 山寨币需要证明相对 BTC 的风险收益值得承担。 |

## 3. 记账与表现

| 术语 | 中文释义 | 本项目中的具体含义 | 对决策的影响 |
|---|---|---|---|
| **NAV** | 净资产值（Net Asset Value） | 某个时间点组合全部资产的总价值。 | 用来比较组合随时间的真实变化。 |
| **unitized NAV** | 单位化净值 | 把外部存取款转换为单位数变化，从而把资金流与投资表现分开。 | 避免把“新存入的钱”误判成投资收益。 |
| **external cash flow** | 外部现金流 | 存入组合或从组合取出的资金，而不是资产价格变化。 | 必须明确标记为 DEPOSIT、WITHDRAWAL 或 NONE。 |
| **cash_flow_resolution_status** | 现金流解析状态 | 未披露时为 `ASSUMED_NONE`（`0`、`NONE`）；也可为 `CONFIRMED_NONE`、`CONFIRMED_AMOUNT`、`UNRESOLVED` 或 `BASELINE_RESET`。 | 无披露按市场表现记账并保持 `FINAL`；明确未解决才是 `PROVISIONAL`。 |
| **cash-flow timing** | 现金流时点 | 本项目把附着在 snapshot 上的现金流视为发生在该 snapshot 估值之前。 | 影响 NAV、基准和回撤计算；时点不能被忽略。 |
| **cost basis** | 成本基础 / 持仓成本 | 购买剩余仓位所对应的已知成本金额。 | 成本未知时保持未知，不会伪造为零。 |
| **P&L** | 盈亏（Profit and Loss） | 当前价值与成本基础之间的差额或比例。 | 需要区分仓位盈亏与组合层面的 NAV Return。 |
| **realized P&L** | 已实现盈亏 | 已经卖出部分产生的盈亏。 | 当前功能不声称提供完整的已实现盈亏、税务批次或手续费分析。 |
| **unrealized P&L** | 未实现盈亏 | 仍持有的仓位按当前价格计算的账面盈亏。 | 只说明剩余仓位的表现，不能当作生命周期收益。 |
| **return** | 收益率 | 某资产、组合或基准在匹配期间的价格/净值变化比例。 | 组合收益必须使用现金流调整后的方法，不能用余额变化代替。 |
| **coverage** | 覆盖率 | 依上下文表示成本数据覆盖率或证据覆盖率。 | 覆盖率低会降低信心；关键数据缺失可直接阻止高置信度新增仓位。 |
| **PROVISIONAL** | 暂定 | 存在未分类的重大余额变化，无法确认 NAV 表现是否为真实投资表现。 | 只能作为暂定结果，不应称为可靠收益或回撤。 |
| **performance_finality** | 表现最终性 | `FINAL`、`PROVISIONAL` 或 `UNAVAILABLE`，描述 NAV/benchmark 是否已经过现金流边界确认。 | 报告只能格式化该字段，不能自行把暂定结果改成最终结果。 |
| **-- / unknown** | 未知 | 截图或来源没有足够信息，例如成本或盈亏显示为 --。 | 保持未知；未知不是零，也不是默认安全。 |

## 4. 市场数据与指标

| 术语 | 中文释义 | 本项目中的具体含义 | 对决策的影响 |
|---|---|---|---|
| **OHLCV** | 开高低收量 | Open、High、Low、Close、Volume，即开盘价、最高价、最低价、收盘价和成交量。 | 是趋势、ATR、波动率和 Volume Profile 的基础历史数据。 |
| **spot price / SpotPrice** | 现货价格 | 某资产在现货市场上的当前价格；SpotPrice 还必须带观察时间和来源。 | 执行计划不能使用没有时间戳的价格。 |
| **completed candle** | 已完成 K 线 | 已经结束的完整时间周期蜡烛线。 | 指标只使用已完成 K 线，避免把未来或未收盘数据带入结果。 |
| **freshness_reference_at** | freshness 参考时间 | 日线 OHLCV 指标使用的最新完整 K 线收盘边界。 | 必须与 `metadata.completed_through` 相同；旧数据缺失该字段时不能作为 fresh hit。 |
| **completed_through** | 已完成至 | Provider metadata 中记录的最新完整 K 线收盘边界。 | 用于 freshness 和 cache reuse，不使用 candle open time 代替。 |
| **no-lookahead** | 无前视 | 计算时只使用决策时点已经可用的数据。 | 防止回放结果看到了当时尚不存在的价格或事件。 |
| **MA / MA20 / MA50 / MA100 / MA200** | 移动平均线 | 指定窗口内价格的平均值，用于观察中长期趋势。 | 只是趋势证据之一，不是单独的买卖信号。 |
| **ATR / ATR14** | 平均真实波幅 | 反映价格波动范围；当前 ATR14 使用 14 个完整真实波幅的简单平均。 | 用于设置波动感知的区间和判断价格是否过度延伸。 |
| **realized volatility** | 已实现波动率 | 根据过去价格变化计算的历史波动程度。 | 高波动通常降低新增配置或即时执行的规模。 |
| **relative volume** | 相对成交量 | 当前成交量相对于参考期间成交量的比例。 | 只能作为趋势/结构的辅助证据，不单独触发交易。 |
| **Volume Profile** | 成交量分布 | 把历史成交量按价格区间分布，观察成交量集中在哪里。 | 是历史成交量集中度 proxy，不是持仓者的精确成本基础。 |
| **POC** | 成交量控制点（Point of Control） | Volume Profile 中成交量最大的价格区间。 | 可作为结构参考，不能独立创建组合风险或交易。 |
| **VAL / VAH** | 价值区间下沿/上沿 | Value Area Low / High，覆盖配置比例成交量的价格区间边界。 | 帮助描述结构区域，不是保证支撑或阻力。 |
| **HVN / LVN** | 高量节点/低量节点 | High Volume Node / Low Volume Node，分别表示成交量集中或稀疏的价格节点。 | HVN 可作区域背景；LVN 只能作背景，不能单独决定动作。 |
| **pullback** | 回撤后的回踩 | 上行或下行结构中的暂时回撤与重新测试。 | 当前执行计划只生成 PULLBACK 模式。 |
| **breakout** | 突破 | 价格离开原有区间或关键结构。 | 当前对 BREAKOUT 返回 WAIT，避免机械追涨。 |
| **market cap** | 市值 | 当前价格乘以可计入流通供应量的估计值。 | 主要用于估值和相对规模比较；由 CoinGecko 等结构化来源提供。 |
| **FDV** | 完全稀释估值（Fully Diluted Valuation） | 假设完整供应量都按当前价格计价的估值。 | 与 market cap 的比例只在经济上适用且输入新鲜时使用。 |
| **FDV / market cap ratio** | FDV/市值比 | FDV 除以 market cap 的派生比例。 | 用于观察潜在稀释差异；由 Python 从同资产输入派生。 |
| **TVL** | 总锁仓价值（Total Value Locked） | 协议或应用中被锁定资产的价值。 | 是协议基本面指标，不等于代币市值，也不等于安全性。 |
| **AUM** | 管理资产规模（Assets Under Management） | ETF 或类似产品管理的资产金额。 | ETF 净流入通常结合 AUM 归一化，缺失 AUM 不会填零。 |
| **capital flow / net flow** | 资金流 / 净流 | 一段期间内流入减去流出的资金。 | 资金流是背景证据；缺失时保持不可用，不填成中性或零。 |
| **ETF / ETF flow** | 交易所交易基金 / ETF 资金流 | 这里主要指美国 BTC/ETH 现货产品及其日/周/月净流入。 | 是资本流因子的一部分，不代表单日流量就足以交易。 |
| **on-chain** | 链上数据 | 直接来自区块链活动的数据，例如地址、转账、交易和区块空间费用。 | 需要资产适用性、来源和时间验证；不把链上指标当成万能信号。 |
| **staking / APY** | 质押 / 年化收益率 | 通过参与网络验证获得的质押收益及其年化表示。 | 高 APY 不能单独证明资产值得持有，还要看通胀、锁定、惩罚、托管和流动性风险。 |
| **L2 / DA** | 二层网络 / 数据可用性 | Layer 2 与 Data Availability；这里关注 Ethereum 是否真正获得结算或 DA 价值捕获。 | L2 活跃不自动等于 ETH 利好，必须证明与 Ethereum 结算或 DA 的关系。 |
| **BTC dominance** | BTC 市占率 | BTC 市值占整个加密市场市值的比例。 | 用作市场环境和 BTC 相对强弱背景，不是自动交易信号。 |
| **breadth** | 市场广度 | 当前实现中，确定性 top-20 市值资产中 30D 收益为正的比例。 | 描述市场参与度；广度弱会使整体配置更保守。 |
| **BTC-relative strength** | 相对 BTC 强弱 | 资产与 BTC 在同一 venue、quote、完成日期和共同时间锚点上的收益差。 | 山寨币缺少关键相对 BTC 证据时只能 HOLD_ONLY，不能新增风险。 |
| **funding rate** | 资金费率 | 永续合约多空双方定期支付的费率。 | 用于判断拥挤度和杠杆背景，不是现货买卖信号。 |
| **open interest** | 未平仓合约量 | 尚未关闭的衍生品合约规模。 | 增长或下降是定位背景，不单独表示方向。 |
| **long/short ratio** | 多空比 | 多头与空头账户或仓位的比例。 | 不同交易所和统计口径不可直接混合；冲突会降低信心。 |
| **futures basis** | 期货基差 | 期货标记价格相对指数价格的差异，当前可按到期时间年化。 | 反映衍生品定价和拥挤度，只作背景约束。 |
| **MVRV / SOPR / LTH net-position change** | 链上周期指标 | 用于比较市值与实现价值、观察已花费输出盈利和长期持有者净仓变化。 | 属于 BTC 周期/链上背景，缺失会降低周期信心，但不能单独触发交易。 |

## 5. 证据、评分与系统

| 术语 | 中文释义 | 本项目中的具体含义 | 对决策的影响 |
|---|---|---|---|
| **Evidence** | 证据记录 | 带 ID、资产、因子、来源、观察/抓取时间、新鲜度、置信度和摘要/值的结构化记录。 | 决策必须能追溯到证据；不能用隐藏推理代替证据。 |
| **source** | 数据来源 | 提供原始事实或发布信息的官方机构、交易所、协议或分析平台。 | 来源层级和方法论决定证据质量。 |
| **provenance** | 来源链 / 溯源 | 记录数据从哪里来、何时获取、经过什么规范化或派生。 | 来源不清、时间不明或方法冲突会降低信心。 |
| **Fact** | 事实包 | Python 从规范化观测中提取的紧凑、可验证事实。 | 模型可以解释事实，但不能改写 Python 事实。 |
| **Factor** | 评分因子 | 把相关事实归类后用于评分的维度。 | 当前六个基础因子恰好是 trend、valuation、fundamentals、onchain、capital_flows 和 relative_strength_btc。 |
| **score** | 分数 | 通常为 0–100 的因子或资产评分。 | 是配置输入，不是 score > 某值就买的直接规则。 |
| **confidence** | 信心 | 对证据完整度、质量和一致性的综合判断。 | 低信心不能被用户输入悄悄抬高为高信心，也不能产生高置信度新增仓位。 |
| **reliability** | 可靠性 | 某条数据或因子在当前决策中可被信任和使用的程度。 | 缺失因子保留原政策权重，但其分数向中性 50 收缩。 |
| **evidence coverage** | 证据覆盖率 | 适用且可用的证据在政策权重下的覆盖程度。 | NOT_APPLICABLE、可选 SKIPPED 和 overlay 不进入适用评分分母；必要失败会降低覆盖率。 |
| **event-risk gate** | 事件风险门 | 独立于六个基础因子的安全、治理、监管和重大事件限制。 | SEVERE/CRITICAL 可以阻止新增风险，但不会把事件风险伪装成第七个基础分数。 |
| **AAVE governance coverage** | AAVE 治理覆盖 | Governance V3 on-chain 与至少一个官方 forum/proposals off-chain source 的组合覆盖。 | 缺任一 source group 都是 `INSUFFICIENT_SOURCE_COVERAGE`，泛新闻不能替代。 |
| **overlay** | 覆盖层 | positioning、BTC cycle、execution context 或 structural risk 等额外背景。 | 可以限制即时部署或降低信心，但不是新的加权基础因子。 |
| **chain liveness** | 链运行状态 | 通过结构化 block/slot/RPC 数据判断链是否仍在正常推进。 | 只适用于 BTC、ETH、SOL、BNB；链数据传输失败不等于链已 HALTED。 |
| **HEALTHY / DEGRADED / HALTED / UNKNOWN** | 健康/降级/停止/未知 | 链运行状态的枚举；HALTED 需要配置的独立来源共同证明严重停滞。 | DEGRADED 会限制部署；HALTED 阻止新增敞口；UNKNOWN 不会被当作健康。 |
| **SUCCESS / FAILED / STALE / CONFLICT** | 成功/失败/过期/冲突 | 每次指标采集的结果状态。 | FAILED、STALE 和 CONFLICT 保留可见并影响信心；不能静默转成中性值。 |
| **NOT_APPLICABLE** | 不适用 | 某资产与指标组合在语义上没有意义，例如 BTC 的 TVL。 | 不进入适用覆盖率；不能误报成失败，也不能为了提高覆盖率使用它。 |
| **SKIPPED** | 跳过 | 可选或 premium 证据没有合资格的已配置 Provider。 | 只用于允许跳过的可选场景；不等同于 NOT_APPLICABLE 或必要数据失败。 |
| **freshness** | 新鲜度 | 观测是否仍在该 metric 的允许时间窗口内。 | 旧数据标记为 STALE，会降低信心或阻止高置信度行动。 |
| **as_of** | 决策截止时间 | 本轮分析允许使用的时间上限。 | 历史回放不能使用截止时间之后的数据。 |
| **observed_at** | 观测时间 | 数据事实实际对应的市场、区块或扫描时间。 | 决定这条证据代表哪个时点，不能用抓取时间替代。 |
| **fetched_at** | 抓取时间 | 客户端取得数据的时间。 | 新抓到的旧历史数据不因此变成当前数据。 |
| **provider** | 数据适配器/提供方 | 负责从某个外部 API 或结构化来源取得并规范化数据的组件。 | Provider 是获取路径，不等于来源权威本身。 |
| **router** | Provider 路由器 | 按固定优先级选择 Provider、缓存和回退路径。 | 路由失败会保留尝试细节；不会伪造成功值。 |
| **normalized data** | 规范化数据 | 已统一单位、时间、资产、来源和状态的结构化数据。 | 引擎只消费规范化数据，不直接依赖交易所或网页格式。 |
| **MetricObservation** | 指标观测记录 | 成功验证后的单条指标历史记录，保存值、来源、时间和新鲜度。 | 可供下一轮比较；历史记录是追加写入的。 |
| **CollectionEvent** | 采集事件记录 | 每次指标采集尝试的记录，包括失败、过期、冲突、不适用和跳过。 | 让报告能说明数据为什么不可用，而不是隐藏缺口。 |
| **cache** | 缓存 | 对已取得的 Provider 响应或不可变历史序列的本地保存。 | 缓存是获取加速器，不是决策权威；过期和不匹配缓存不能冒充当前证据。 |
| **AUTO / CACHE_ONLY / REFRESH** | 自动/仅缓存/刷新 | AUTO 先复用新鲜数据，CACHE_ONLY 不联网，REFRESH 刷新可变当前数据。 | CACHE_ONLY 缺数据时保持缺失；不能偷偷联网或填补数值。 |
| **snapshot** | 组合快照 | 某一时刻经过校验的持仓和估值输入。 | 是历史记账、NAV、回撤和复盘的时间锚点。 |
| **decision** | 决策记录 | 基于某个 snapshot 和 policy 产生的资产评估、目标、动作和理由。 | 历史决策追加保存，不能覆盖旧 rationale。 |
| **append-only** | 只追加 | 新记录写到末尾，不修改既有历史记录。 | 保留可审计性；状态变化写成新的事件。 |
| **JSONL** | JSON Lines | 每行一个 JSON 记录的持久化格式。 | 适合追加和逐条校验；无效记录不能写入历史。 |
| **schema** | 数据模式 | 对 JSON 结构、字段类型、枚举和约束的机器可读定义。 | 模型、Schema、fixture 和文档需要保持一致。 |
| **canonical policy** | 规范策略 | config/policy.json 中唯一的机器可读政策来源。 | 稳定资金、评分权重、上限和阈值不能在其他地方悄悄复制一份。 |
| **resolved policy** | 已解析策略 | 将默认策略、允许的输入覆盖和分类规则解析后的确切策略。 | 决策保存它以便未来重放，不依赖未来配置文件的变化。 |
| **policy hash** | 策略哈希 | 已解析策略的确定性 SHA-256 标识。 | 用来确认历史决策与当时实际使用的策略一致。 |
| **DecisionReviewPacket** | 决策复核数据包 | 供报告阶段使用的资产摘要、权重、动作、风险、缺失数据和 overlay 数据包。 | 是已验证的交接边界；报告不能重新计算或覆盖金融结果。 |
| **ReportPacket** | 报告数据包 | 已 finalized 的 regime、分数、权重、动作、区间、历史变化、数据质量和失败日志。 | 报告只能解释其中的最终值，不能自行改变 Action 或 risk flag。 |
| **Python-first / deterministic** | Python 优先 / 确定性 | 能从结构化数据推导的数学、校验和风险结论由 Python 负责。 | 模型只能做有界语义判断，不能重算或覆盖记账、评分、配置和风险结果。 |
| **LUNA_MAX** | 指定模型档位 | 当前所有 Luna 语义阶段唯一允许使用的目标。 | 只影响有界提取、研究和解释，不拥有组合风险或资金权威。 |
| **API / API key** | 接口 / 接口密钥 | API 是程序访问外部数据的接口；API key 是可选认证凭证。 | 密钥只通过环境变量提供，不写入配置、缓存、JSONL、日志或报告。 |
| **TLS / DNS** | 传输层安全 / 域名解析 | TLS 验证 HTTPS 证书和主机名；DNS 把域名解析到网络地址。 | TLS、DNS、超时或 HTTP 错误表示数据不可用，不表示链停止或结论为零。 |
| **RPC** | 远程过程调用 | 读取区块链节点数据的接口，例如最新区块、slot 或 finalized 状态。 | 是观测传输方式，不是安全、治理或监管权威。 |
| **EventScanner / source catalog** | 事件扫描器 / 来源目录 | 按固定 allowlist 检查安全、协议、治理和监管来源。 | 页面内容不能自行添加 URL、扩大范围或改变扫描指令；覆盖不足必须显式报告。 |

## 6. 一条决策链

阅读报告时，可以按下面的顺序理解一个结论：

    Evidence
      -> Fact
      -> Factor score / confidence
      -> market regime + event-risk gate + overlay
      -> target weight
      -> current vs target deviation
      -> rebalance threshold
      -> Action

高分不保证 INCREASE：稳定资金底线、集中度、风险状态、事件风险、BTC 相对机会成本、
数据覆盖率和技术执行条件都可能让最终结果成为 HOLD、WAIT、HOLD_ONLY 或 NO_TRADE。

`Data Confidence` 衡量证据覆盖、新鲜度、来源质量、独立来源冗余和信号一致性；
`Regime Confidence` 衡量市场状态判断的证据把握；`Decision Confidence` 衡量当前
动作结论的证据把握。三者都是 Python 派生值，不能由 LLM 重算或抬高。`PROVISIONAL`
和 `BLOCKED` 是显式状态，不等于零分或安全。
